# INSTALL - Setting up AI_auto from scratch

This is the single source of truth for installing the infrastructure on a new
machine or for a new colleague. It is written for **two readers**:

- **A human owner**, who must create the accounts, pay for the paid plans, and
  complete the interactive logins. Read Parts A and B, then hand the machine to
  the agent.
- **A Claude (or other agent) doing the install**, who executes Part C top to
  bottom, stopping at every `HUMAN STEP` and asking the owner to act.

> The agent can automate everything **except** creating accounts, accepting paid
> plans, completing OAuth/browser logins, and generating API keys/tokens. Those
> are marked `HUMAN STEP`. Everything else the agent can do.

---

## Part A - Accounts and licenses you must bring

Create these **before** the install. The owner must do this; an agent cannot.

| Service | Needed for | Cost | What you end up with |
|---|---|---|---|
| **Anthropic / Claude** | Every AI session (`/work`, `/close`, `claude -p`). The core engine. | **Paid** - Claude Pro/Max subscription or API credits | An account you can `claude login` into |
| **Overleaf** | Manuscript sync (`helpi 2/3/4`) | **Paid** - git integration is a premium feature | An account + the `overleaf_session2` cookie |
| **GitHub** | Code repos (`helpi 23`), and the NoteTaker spool | Free | An account + `gh auth login` |
| **Google (Gemini)** | `helpi 25` forum; NoteTaker transcription | Free tier is enough | A Google account for `gemini` CLI login |
| **OpenAI (Codex)** | *Optional* - `helpi 24/25`, slides, one-pager when run with `-Agent codex` | **Paid** - ChatGPT Plus or API | An account you can `codex login` into |
| **Supabase** | *Only if installing NoteTaker* (voice notes) | Free tier is enough | A project + deployed edge function (see Part F) |

**Minimum to be useful:** Anthropic + Overleaf + GitHub. Gemini adds the forum.
Codex is optional. Supabase/NoteTaker is a separate, optional add-on.

## Part B - Software to install

> **`TOOLS.md` is the companion to this section.** It is generated by `helpi 29`
> and records what is actually on the current machine, with versions and paths.
> This section is the *plan*: what to install on a new one, in order, with the
> traps. Per-tool gotchas live in `known_issues.md`. Do not merge the three.
>
> On the old machine, before you wipe it: run `helpi 29` and keep `TOOLS.md`.
> That file is your target state.

### B1 - Tier 1: nothing works without these

| Software | Why | Install |
|---|---|---|
| **Git** | Everything | https://git-scm.com/download/win |
| **PowerShell 7** | Every `helpi` script | `winget install Microsoft.PowerShell` |
| **Claude Code CLI** | The agent | https://claude.ai/download |
| **Node.js** (LTS) | Provides the agent CLIs via npm | https://nodejs.org |
| **GitHub CLI (`gh`)** | Code push, auth | https://cli.github.com |
| **VS Code** | `helpi 5` opens projects here | https://code.visualstudio.com |

### B2 - Tier 2: LaTeX chain

Install MiKTeX first; `latexmk`, `latexdiff` and `bibtex` ship with it.

| Software | Why | Install |
|---|---|---|
| **MiKTeX** | `helpi 5/6` compile | https://miktex.org/download |
| **Strawberry Perl** | Runs `latexdiff` for `submit.ps1` | https://strawberryperl.com |

> **Trap.** Complete MiKTeX's first-run setup interactively before relying on
> `helpi 6`. Non-interactive `latexmk` can block on the package-install prompt.

### B3 - Tier 3: agent CLIs

```powershell
npm install -g @google/gemini-cli @openai/codex
npm install -g supabase          # only if installing NoteTaker
```

**Antigravity (`agy`) is not npm and must be pinned to v1.0.8.** v1.0.9 and
v1.0.10 have an OAuth `token exchange failed` regression that breaks login, and
there is no version-pin flag, so never run the installer script or accept an
update prompt. It is interactive-only and hangs when driven headlessly, so it is
never wired into automation; `gemini --model gemini-2.5-flash` is the automation
path. See `known_issues.md` #37.

### B4 - Tier 4: numerical and research tools

Install only what the projects in flight actually need. None of these are
required for the infrastructure itself to run.

| Software | Why | Install |
|---|---|---|
| **Python (miniconda)** | Project `code/`; deliberately **not** on PATH | https://docs.conda.io/en/latest/miniconda.html |
| **R** | Project `code/`; deliberately **not** on PATH | https://cran.r-project.org |
| **Gurobi** | `jr_optlib` exact benchmarks, selected MIP/MIQP | `conda install -c gurobi gurobi` + licence |
| **QGIS LTR** | Maps and geoprocessing | https://qgis.org/download |
| **Biogeme** | Discrete choice estimation | see below |

**Python environment rules, learned the hard way:**

1. **Never install a heavy numerical stack into `base` or `pyopt`.** Mixing a
   pip wheel with the conda Intel OpenMP runtime aborts on a duplicate
   `libiomp5md.dll`. Do not paper over it with `KMP_DUPLICATE_LIB_OK`
   (`known_issues.md` #45).
2. **Venvs go in `C:\Users\<user>\venvs\`, never inside OneDrive.** A venv is a
   build artifact of ~25,000 files that must not sync. Point the project's
   `.vscode/settings.json` at the interpreter instead (`known_issues.md` #51).

```powershell
# Biogeme, as an example of the pattern
python -m venv C:\Users\rich\venvs\biogeme313
C:\Users\rich\venvs\biogeme313\Scripts\python.exe -m pip install biogeme==3.3.4
C:\Users\rich\venvs\biogeme313\Scripts\python.exe C:\Users\rich\venvs\biogeme313\biogeme_check.py
```

Use Biogeme **3.3.x, never 3.2.x**: 3.2.14 is sdist-only on PyPI and would need
MSVC Build Tools, while 3.3 ships a pure-Python wheel. The cost is that 3.3 broke
the 3.2 API, so published examples need porting (`known_issues.md` #51).

QGIS needs no global configuration. Install it, then run `helpi 28` inside any
project that needs maps; it writes the workspace-scoped interpreter config there
and nowhere else (`known_issues.md` #50).

## Part C - Install runbook (agent-executable)

Run from PowerShell on Windows. Steps marked `HUMAN STEP` pause for the owner.

### 1. Clone the infrastructure
```powershell
cd "<your JR folder>"
git clone https://github.com/jepperich69/ai-infrastructure.git AI_auto
```

### 2. Run the setup wizard
```powershell
cd AI_auto
.\scripts\setup.ps1     # or, once helpi is on PATH: helpi 21
```
This writes `scripts\config.local.ps1` (publications root + git identity), adds
the `helpi` function to the PowerShell profile, registers the 4-hour auto-sync
task, and offers the Overleaf bulk-import. It does **not** touch any account.

### 3. `HUMAN STEP` - log in to the agent CLIs
The owner runs each of these once; they open a browser for OAuth:
```powershell
claude login        # Anthropic  (required)
gh auth login       # GitHub     (required)
gemini              # Google     (required for helpi 25; first run triggers login)
codex login         # OpenAI     (optional)
```
> Agent: you cannot complete these. Ask the owner to run them and confirm each
> succeeded before continuing.

### 4. `HUMAN STEP` - Overleaf cookie, then import projects
The owner logs into overleaf.com, opens `F12 -> Application -> Cookies`, and
copies the value of `overleaf_session2`. Then:
```powershell
.\scripts\fetch_overleaf_projects.ps1   # paste the cookie when prompted
.\scripts\link_projects.ps1             # clone + register everything
```

### 5. Copy the shared Claude config
The global `~/.claude/CLAUDE.md` and the skills/commands are not in this repo.
Copy them from the owner's existing machine or a colleague:
```powershell
# example: from a synced OneDrive or a shared location
Copy-Item "<source>\.claude\CLAUDE.md"  "$env:USERPROFILE\.claude\CLAUDE.md"
Copy-Item "<source>\.claude\skills"     "$env:USERPROFILE\.claude\" -Recurse
```

### 6. Verify (see Part E)

## Part D - Environment variables

**AI_auto core needs none.** The agent CLIs carry their own auth from the logins
in step 3.

Environment variables are required **only for NoteTaker** (Part F):

```powershell
setx GEMINI_API_KEY     "<google ai studio key>"
setx GITHUB_WRITE_PAT   "<fine-grained PAT, contents:write on notetaker-inbox>"
```
> Note: `setx` values appear in **new** shells only. Open a fresh terminal after
> setting them. Keep keys out of any committed file.

## Part E - Verification / smoke tests

```powershell
helpi 13                       # status dashboard - should list registered projects
helpi 3 <SomeProject>          # pull one Overleaf project - tests Overleaf auth
helpi 6 <SomeProject>          # compile LaTeX - tests MiKTeX
echo "hi" | gemini --model gemini-2.5-flash   # tests Gemini login (if used)
```
A clean `helpi 13` plus a successful `helpi 3` means the core is working.

## Part F - NoteTaker (optional voice-note pipeline)

NoteTaker is a **separate repo** with its own deep guide:
`NoteTaker/RECOVERY_GUIDE.md`. It roughly doubles the setup. Only do this if the
owner wants voice-note capture. Summary of what it additionally needs:

- A private GitHub repo `notetaker-inbox` with a release tagged `inbox-spool`.
- Two GitHub fine-grained PATs: a **read-only** one on the phone, a **write** one
  as a Supabase secret.
- A **Supabase** project with the `notetaker-proxy` edge function deployed and
  secrets set (`GITHUB_WRITE_PAT`, `GITHUB_OWNER`, `GITHUB_REPO`). The free tier
  auto-pauses after 7 days idle; the watcher pings it to stay alive (see
  `RECOVERY_GUIDE.md` section 2b).
- `GEMINI_API_KEY` and `GITHUB_WRITE_PAT` set as user env vars (Part D).
- The phone PWA deployed to GitHub Pages.
- The watcher running: `powershell -File NoteTaker\code\notetaker_watcher.ps1`
  (it auto-starts at logon via the Startup-folder launcher).

## Part G - Cellar compute server (optional; replacing any of its three machines)

The cellar is a home PC running WSL2 that takes long Gurobi/Python jobs; an Android phone relays Wake-on-LAN from
outside home. Reference: `compute_server/README.md`. The machine-specific values live in
`compute_server/local/cellar_config.json`, which is **gitignored** (the repo is public). On the owner's machines
OneDrive carries `local/`; a fresh clone has only the template `compute_server/cellar_config.example.json`.

Check at any point, without waking anything: `python scripts\cellar.py doctor` (every FAIL names its fix).

### G1 - New laptop (cellar and phone unchanged)
1. Parts B-C as usual. Tailscale: install it and `HUMAN STEP` log in to the same tailnet.
2. Config: if OneDrive brought `compute_server/local/cellar_config.json`, check `laptop_pyopt` and `jr_optlib`
   paths. Otherwise copy the example there and fill it in (values: old config, or `local/cellar_setup_log.md`).
3. Key, either way:
   - **Copy** `~/.ssh/id_ed25519_cellar` and `.pub` from the old laptop (nothing else to change), or
   - **New key:** `ssh-keygen -t ed25519 -N "" -C laptop-claude-to-cellar -f $HOME\.ssh\id_ed25519_cellar`, then
     authorize the `.pub` on both ends while the old laptop still works:
     `type id_ed25519_cellar.pub | ssh cellar "cat >> ~/.ssh/authorized_keys"` and
     `type id_ed25519_cellar.pub | ssh cellar-relay "cat >> ~/.ssh/authorized_keys"` (run from the old laptop).
     Without the old laptop: `HUMAN STEP` paste the key on the cellar PC (WSL, `~/.ssh/authorized_keys`) and in
     Termux on the phone.
4. `~/.ssh/config`: add the `Host cellar` and `Host cellar-relay` blocks shown in `compute_server/README.md`.
5. First connect to each: compare the fingerprint with `cellar_host_key` / `relay_host_key` before accepting.
   (For the phone, use Git's `ssh-keyscan`; Windows OpenSSH 9.5's cannot negotiate with it.)
6. Profile function in both PS5 and PS7 profiles:
   `function cellar { & "<AI_auto>\compute_server\laptop\wake-cellar.ps1" -Ssh }`
7. Gurobi: the WLS licence file goes to the new laptop as usual; the cellar already has its own copy.
8. Verify: `cellar.py doctor` all OK, then `cellar.py status` and `cellar.py env`.

### G2 - New cellar PC
1. On the new PC, give a Claude Code session `compute_server/cellar_setup_instructions.md` (copy it over; the PC
   gets no OneDrive). It ends with a REPORT BACK block.
2. On the laptop, update `local/cellar_config.json` from that block: `mac`, `lan_ip`, `wol_broadcast`,
   `tailscale_ip`, `cellar_host_key`, `cellar_windows_user`. Remove the old `cellar` line from `~/.ssh/known_hosts`.
3. `scp` the Gurobi licence to `~/gurobi.lic` (mode 600), then `cellar.py install` (job helper + idle-sleep timer).
4. New MAC: regenerate the relay's wake command (G3 step 5 only).
5. Verify: `cellar.py doctor`, `cellar.py env`, a short test job, then a sleep-then-wake test.

### G3 - New phone relay
1. `HUMAN STEP` On the phone: Tailscale (log in, disable key expiry in the admin console), Termux and
   Termux:Boot (GitHub builds; Play/F-Droid installs may be blocked by Play Protect), open Termux:Boot once.
   Then every setting in the phone table in `compute_server/README.md` (Always-on VPN, battery, auto start,
   wake lock, recents lock, no automatic system updates). Without them the relay dies after a night-time reboot.
2. In Termux: `pkg install openssh python`, `passwd` (temporary), `sshd`, `termux-wake-lock`. Note the phone's
   Tailscale IP and its Termux user name.
3. From the laptop, with password login: `scp -P 8022 compute_server/phone/relay-setup.sh <user>@<phone ip>:`
4. `type $HOME\.ssh\id_ed25519_cellar.pub | ssh -p 8022 <user>@<phone ip> "sh relay-setup.sh <mac> <wol_broadcast[0]>"`
5. Check key login works, then `ssh -p 8022 <user>@<phone ip> "sh relay-setup.sh lock"` (key only).
6. Update `relay_ip` and `relay_host_key` in the local config and the `Host cellar-relay` block (`User` = the
   Termux user). Verify: `ssh cellar-relay wake-cellar` prints "sent (4/4)".
7. Reboot test: restart the phone, unlock it, touch nothing; `cellar.py doctor` must show the relay OK within a few minutes.

## What the agent can and cannot do - quick reference

**Agent can:** clone the repo, run `setup.ps1`, write `config.local.ps1`, install
CLIs via npm, set env vars, clone/register Overleaf projects (once given the
cookie), deploy the Supabase function via the `supabase` CLI, run all smoke tests.

**Agent cannot (HUMAN STEP):** create any account, accept/pay for a plan, complete
an OAuth/browser login, or generate an API key or PAT. Provide the agent with the
key *values* (or complete the logins yourself) and it handles the rest.
